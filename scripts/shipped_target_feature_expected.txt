# Shipped-path compile-time `target_feature` arms this repo keeps ON PURPOSE
# (Issue 847 T3). Key: `<path>::<enclosing fn>#<ordinal within that fn>` —
# LINE-FREE, because a line number drifts on every edit above it and a pin
# file that reds on noise is one people delete (`arm_reach_gate`'s rule). A
# dispatcher contributes two rows (the positive arm and its `not(any(..))`
# complement) because both are the same compile-time construct.
#
# Format: `<key> = <reason>`. A row without a reason is REFUSED, and a row
# whose site is gone reds too — so this file cannot only ever loosen.
#
# ⛔ The bar for a row is a MEASUREMENT or a structural argument, never "not
# fixed yet": a row of the latter kind is a backlog wearing a pin, which Issue
# 785's rule forbids, and the thing behind it is latency on every call.

# ── the runtime probe's OWN body — the correct pattern, not the defect ─────
# `#[cfg(target_feature = "avx2")] { true }` inside the CPUID probe: a build
# that already targets AVX2 need not ask the CPU. This is the thing every
# other dispatcher should CALL, and it is indistinguishable from the defect by
# any predicate — the same attribute doing the opposite job. Issue 847's own
# Non-goals section names it.
crates/katgpt-types/src/simd/mod.rs::is_avx2_fma_available#1 = the probe's own short-circuit: a build with AVX2 already on skips CPUID. Issue 847 Non-goals.
crates/katgpt-types/src/simd/mod.rs::is_avx2_fma_available#2 = the probe's own `not(...)` arm, the CPUID read itself. Issue 847 Non-goals.

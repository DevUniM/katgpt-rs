# Pins for scripts/shared_temp_path_drift_sweep.py — EVERY contract repo.
# Issue 832 T3, the cross-repo half of scripts/shared_temp_path_gate.py.
#
# Format, 3 whitespace-separated fields:
#
#   <repo> <min_temp_sites> <max_fixed>
#
# Re-pin DELIBERATELY, in the commit that changes the measured value, with the
# reason in the commit message.
#
# ── why there are only TWO columns ──────────────────────────────────────────
# There is no `min_rs_files` column. `orphaned_attr_drift_floors.txt`,
# `platform_dead_code_drift_floors.txt` and `percentile_drift_floors.txt`
# already floor this identical `tracked_files(repo, "*.rs")` call over this
# identical population, and a fourth copy is a fourth number to re-pin on
# ordinary churn — they already disagree with each other about the number.
# The delegation is ASSERTED, not assumed (len_derived_drift_sweep's rule):
# every repo pinned here must still carry a NON-ZERO min_rs_files row in
# orphaned_attr_drift_floors.txt, and a delegated file the sweep cannot PARSE
# is refused rather than read as an empty dict.
#
#   min_temp_sites  the PREDICATE floor. A regex regression that stops matching
#                   `env::temp_dir()` collapses the population to ~0 over an
#                   unchanged walk, and then every ceiling below passes
#                   vacuously. Pinned well under the measured value so ordinary
#                   churn does not re-pin it, while a collapse still reds.
#                   ⚠ VACUOUS in riir-auth (0 sites) — that repo has .rs files
#                   and no temp_dir call at all, which is exactly why the walk
#                   floor is delegated rather than dropped: in a 0-site repo
#                   the delegated min_rs_files is the ONLY blindness detector
#                   there is (Issue 783's population shape).
#
#   max_fixed       the RATCHET, at measured.
#
# ── why max_fixed is a RATCHET and not a wall ───────────────────────────────
# Measured 2026-09-18 over the 13 canonical repos present on this box: 100
# fixed `env::temp_dir().join("literal")` sites, of which 98 are NOT in
# katgpt-rs. A wall would demand 98 repairs across ten trees in one change, and
# AGENTS.md is explicit that a cross-repo repair is not landed until it is
# COMMITTED in the sibling with a cited SHA (Issue 798 — measured, two tracked
# files recorded sibling repairs as landed and green when two of five existed
# and both sweeps were red for six hours). A wall here makes the next repo to
# join somebody's emergency, and a sweep that always reds is a sweep nobody
# runs. This is instrument_reachability_drift_sweep's answer, for its reason.
#
# ⚠ That is NOT a claim the 98 are acceptable — they are a real backlog, filed
# as Issue 832 T5 with these per-repo counts, and each repo's rows stay its
# owner's to adjudicate. The ratchet's job is that the commit adding the NEXT
# one reds. Sampled for over-capture and it is not over-capture: riir-ai's
# `go_bonsai_cache_test.bin` and `test_egl_roundtrip.bin` are #[test] bodies
# writing a fixed filename, byte-for-byte the shape that produced this repo's
# own five-at-once `"File too small for header"` failures.
#
# ── katgpt-rs's row does not restate its gate ───────────────────────────────
# `max_fixed 2` is the two adjudicated examples/ rows, and a count comparison
# against it would be true by construction — this sweep and the gate call the
# same scan(). The sweep asserts the GATE'S VERDICT over this repo instead
# (numbering_drift_sweep's rule), so a stale membership row in
# shared_temp_path_expected.txt reds the sweep too.
#

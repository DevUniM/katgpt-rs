Branch: `develop`

## Why this issue exists

`PuctPlayer` is a pure tree search: no transposition handling, no cross-game memory — every `select_move` starts a cold tree and re-pays for knowledge it already produced. The shipped Engram substrate (O(1) ~48 ns hash-addressed lookup, BLAKE3-committed frozen tables, `EngramHotSwap` freeze/thaw) is the modelless fix: mine a frozen value/prior table from offline self-play, sigmoid-gate its read into node expansion (prior sharpening + Q init), keyed on the TT discipline `(board, ko_point, to_play)`. Prior art is real (M-MCTS, AAAI 2018 Outstanding Paper) and the proposal names our deltas honestly — the arena G5 is also the test of the deltas.

## ⚠ Arena-infra finding (verdict round 1) — "existing arena infra" does NOT do what T3 needs

All four existing harnesses (`native_puct_winrate.rs`, `wasmi_puct_winrate.rs`, `wasmi_puct_int8_winrate.rs`, …) play **PUCT vs GREEDY** at `NUM_GAMES = 20`, colour alternating across different seeds, each seed played once in one colour. There is **no PUCT-vs-PUCT head-to-head driver** and **no paired design**. T3 requires a new driver (T3.1 below); until it exists, no G5 number can be produced.

## Honest caveats (carried from the proposal — READ FIRST)

1. **Go is (nearly) Markovian** — the #1 inventor's-regret risk. The board features already encode the state; this adds cross-game experience reuse, not new information. **Second inventor's-regret risk (sharper):** M-MCTS's generalization came from kernel regression over NEIGHBOURING states — hard hash routing has no neighbourhood, so the mechanism the paper's win rested on is absent by construction. The prior points toward FAIL; that is fine — the gate decides.
2. **Collision dilution** — the gate MUST be count-based (a slot seen once is a rumor; 500× is a statistic). Last-write-wins at build means a collided slot carries a wrong value with full confidence.
3. **Superko approximation** — the crate tracks simple ko only; the TT key is an approximation under superko. Document it; never widen the key silently to "fix" it without measuring the hit-rate collapse.
4. **Table staleness is by design** (frozen, mined against one distribution) — fine for the arena POC; production consumers need a re-mining cadence via `EngramHotSwap` (substrate exists).
